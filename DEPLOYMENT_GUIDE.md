# Deployment Guide — Pokémon Explorer
### React (Vercel) + FastAPI (Render) + Supabase (Postgres)

---

## Part 0 — Set up Supabase (database)

The backend stores favorite Pokémon in a Supabase Postgres database. Set this up first, because the backend needs its keys to run, both locally and on Render.

### 0.1 Create an account, organization and project

1. Go to **supabase.com** and sign in (GitHub login is easiest).
2. Click **New organization**, give it a name (e.g. `pokemon-class`), keep the defaults (Personal / Free), and create it.
3. Inside the organization, click **New project** and fill in:
   | Setting | Value |
   |---|---|
   | Name | `pokemon-explorer` (or anything) |
   | Database Password | Generate one and **save it somewhere safe** |
   | Region | Closest to you / your Render region |
4. Click **Create new project** and wait a minute or two while it provisions.

### 0.2 Create the `favorites` table

1. In the left sidebar, open **SQL Editor** → **New query**.
2. Paste this and click **Run**:

```sql
CREATE TABLE favorites (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    pokemon_id BIGINT NOT NULL,
    pokemon_name TEXT NOT NULL,
    pokemon_image TEXT NOT NULL,
    chosen_at TIMESTAMPTZ DEFAULT NOW()
);
```

3. Supabase will show a warning that the new table has **Row Level Security (RLS)** disabled. Choose **Run and enable RLS**.
4. Open **Table Editor** in the sidebar and confirm the `favorites` table exists (it will be empty).

> **Why enable RLS?** With RLS on and no policies, nobody can read or write the table through Supabase's public API using the public (anon) key. Only your backend, using the service role key, can access it. That's exactly what we want: the browser never talks to the database directly.

### 0.3 Copy your API keys

1. Go to **Project Settings** (gear icon) → **API Keys**.
2. Copy the **`service_role`** key.
   - It lives under the **Legacy API Keys** tab. On newer dashboards you may instead create/copy a **secret** key (`sb_secret_...`), which works the same way here.
3. Go to **Project Settings** → **Data API** and copy the **API URL**. It looks like:
   ```
   https://<your-project-ref>.supabase.co
   ```

> ⚠️ **The service role key is a secret.** It bypasses RLS and has full access to your database. Only ever put it in the backend's `.env` and in Render's environment variables. Never commit it to GitHub, never put it in the frontend, and never give it a `VITE_` prefix.

### 0.4 Put the keys in the backend `.env`

Create (or edit) `backend/.env`:

```env
SUPABASE_URL=https://<your-project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<paste-your-service-role-key-here>
```

> Use the exact variable names your backend code reads (check `main.py`). The names above are the ones used throughout this guide. Make sure `supabase` is listed in `backend/requirements.txt`.

## Part 1 — Run it locally first

**Backend:**
```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```
Visit `http://localhost:8000/docs` — you should see the Swagger UI and be able to test `/pokemon/pikachu`.

Also try saving a favorite, then open Supabase → **Table Editor** → `favorites` and confirm a new row appeared. If it did, the database connection works.

**Frontend:**
```bash
cd frontend
npm install
npm run dev
```
Visit `http://localhost:5173`, search "pikachu", confirm the card renders.

Once both work locally, you're ready to deploy.

## Part 2 — Push the project to GitHub

```bash
cd pokemon-explorer
git init
git add .
git commit -m "Initial commit"
```

Create a new empty repo on GitHub (no README/license), then:

```bash
git remote add origin https://github.com/<your-username>/pokemon-explorer.git
git branch -M main
git push -u origin main
```

Your `.env` file will **not** be pushed (it's in `.gitignore`) — that's intentional. Secrets/config, including your Supabase service role key, never go to GitHub.

Before pushing, run `git status` and make sure `.env` does not appear in the list of files to be committed.

## Part 3 — Deploy the backend to Render

1. Go to **render.com** and sign in (GitHub login is easiest).
2. Click **New +** → **Web Service**.
3. Connect your GitHub account and select the `pokemon-explorer` repo.
4. Configure the service:
   | Setting | Value |
   |---|---|
   | Name | `pokemon-api` (or anything) |
   | Root Directory | `backend` |
   | Runtime | Python 3 |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
   | Instance Type | Free |
5. **Before clicking Create, add the environment variables.** Scroll down to **Environment Variables** (under *Advanced* if collapsed), click **Add Environment Variable**, and add each value from your backend `.env`:
   | Key | Value |
   |---|---|
   | `SUPABASE_URL` | `https://<your-project-ref>.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | your service role key from Part 0.3 |

   > Render doesn't have your `.env` file (it was never pushed to GitHub), so these must be entered here by hand. Keys must match your `.env` names exactly, with no quotes and no extra spaces.
   >
   > Forgot to add them? You can do it later under your service → **Environment** tab. Saving triggers a redeploy.
6. Click **Create Web Service**. Render will build and deploy — this takes a couple of minutes.
7. Once live, Render gives you a URL like:
   ```
   https://pokemon-api.onrender.com
   ```
8. **Test it**: open `https://pokemon-api.onrender.com/docs` and try `/pokemon/pikachu`. If you get JSON back, the backend is live. Then save a favorite and check Supabase's Table Editor to confirm the database connection works from Render too.

> Note: On Render's free tier, the service "sleeps" after inactivity and the first request after sleeping can take 30–60 seconds to wake up. That's normal — good talking point for students about free-tier limitations.

## Part 4 — Deploy the frontend to Vercel

1. Go to **vercel.com** and sign in with GitHub.
2. Click **Add New...** → **Project**.
3. Import the `pokemon-explorer` repo.
4. Configure the project:
   | Setting | Value |
   |---|---|
   | Framework Preset | Vite |
   | Root Directory | `frontend` |
   | Build Command | `npm run build` (default) |
   | Output Directory | `dist` (default) |
5. Before deploying, expand **Environment Variables** and add:
   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `https://pokemon-api.onrender.com` (your Render URL from Part 3, **no trailing slash**) |

   > Note that the frontend gets **only** the backend URL. No Supabase keys go here.
6. Click **Deploy**. Vercel builds and deploys — usually under a minute.
7. You'll get a live URL like:
   ```
   https://pokemon-explorer.vercel.app
   ```

## Part 5 — Test the full deployed stack

Open your Vercel URL, search for a Pokémon, and save one as a favorite. The request path is now:

```
Vercel (React)  →  Render (FastAPI)  →  PokéAPI
                          ↓
                  Supabase (Postgres)
```

If something fails, check in this order:
1. **Browser console (F12)** — look for a CORS error or a failed fetch.
2. **Render logs** — Render dashboard → your service → *Logs* tab, to see if the request even arrived and whether the backend threw an error.
3. **Frontend environment variable** — confirm `VITE_API_URL` on Vercel exactly matches your Render URL (typos or trailing slashes are the #1 cause of failures).
4. **Backend environment variables** — if search works but favorites fail, check that `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` on Render are correct (no missing characters, no quotes, names match the code).
5. **Supabase Table Editor** — confirm the `favorites` table exists and check whether rows are being added.
6. If you change an env var on Vercel, you must **redeploy** (Vercel → Deployments → ⋯ → Redeploy) — env var changes don't apply retroactively to old builds. On Render, saving env var changes redeploys automatically.

---

## Part 6 — What to update after every future code change

- **Backend change** → push to GitHub → Render auto-redeploys (if auto-deploy is on, which is default).
- **Frontend change** → push to GitHub → Vercel auto-redeploys.
- Both platforms redeploy automatically on every `git push` to `main`, since they're connected directly to the GitHub repo.
- **Database schema change** → run the new SQL in Supabase's SQL Editor. This is not deployed via git.
